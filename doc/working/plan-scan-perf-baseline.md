# Plan — R46 Scan Path Perf Baseline

Task breakdown for implementing `R46-scan-perf-baseline.md`. See
`doc/working/design-scan-perf-baseline.md` for the design.

**Priority:** the crow-cli end-to-end layer is the primary deliverable
(the regression sentinel); the C++ layer is a correctness UT only
(verify sync `scan` deep-pagination pushdown works; no perf microbench).

## Tasks

### Layer 1 (primary) — crow-cli scan bench

- [ ] T1 — Add `--scan-limit`, `--scan-prefix`, `--scan-start-after`
      CLI args to `RunArgs` in `app/crow-cli/src/commands/bench.rs`
      (defaults: 1, empty, empty — preserve backward compat).
- [ ] T2 — Add `scan_limit`, `scan_prefix`, `scan_start_after` fields
      to `BenchConfig` in `app/crow-cli/src/bench/runner.rs`; wire
      them from `RunArgs` in `bench_benchmark`.
- [ ] T3 — Update the `OpKind::List` arm in `runner.rs` (line 593) to
      use `cfg.scan_prefix`, `cfg.scan_start_after`, `cfg.scan_limit`,
      `cfg.read_mode`, `cfg.min_slot_policy.to_min_slot()` instead of
      the hardcoded values.
- [ ] T4 — Build + smoke-test: `pixi run -- cargo build --release
      -p crow-cli`; run `bench run --workload list --scan-limit 10
      --pre-populate 1000` and confirm it returns scan results, not
      the stub `limit=1` behavior.
- [ ] T5 — Write `tools/bench-scan-regression.sh` mirroring
      `bench-write-regression.sh`: a `run_bench` helper that drives
      `crow-cli bench run --workload list` with the scan flags +
      pre-populate + read-mode, parses JSON with jq, appends to
      `doc/working/bench-scan-regression.tsv`. Configs covering:
      full-keyspace (limit >= keyspace), bounded limit (10/100/1k/10k
      over 100k), deep pagination (start_after near end + from-start
      companion for the over-fetch proxy), value-size sweep (64B/1KiB/
      16KiB), prefix range, read-mode split (linearizable vs minslot).
- [ ] T6 — Run the script, verify it completes and the TSV is
      well-formed; check run-to-run variance < ~5% on a quiet machine.

### Layer 2 (secondary) — sync `scan` start_after correctness UT

- [ ] T7 — Add `ReadPath.ScanStartAfterCursor*` UT(s) in
      `lib/crow-tree/tests/integration/read_path_test.cpp` mirroring
      `AsyncScan.StartAfterCursorSkipsEarlierEntries`: build a
      multi-leaf tree, scan with `start_after` near the end + small
      `limit`, verify only keys strictly greater than the cursor are
      returned (not the whole prefix), in order, with the correct
      first key. Also verify `start_after` + `limit` truncation.
- [ ] T8 — Run `pixi run test-tree-ct`, verify the new UT passes.

### Capture + docs

- [ ] T9 — Capture machine info (CPU, cores, page size) via
      `sysctl` / `uname`.
- [ ] T10 — Write `doc/working/scan-perf-baseline.md` with: the

## Notes

- The crow-cli scan JSON report uses `by_op.scan.latency_us` (per
  `runner.rs` line 723) — the script parses that, mirroring how
  `bench-read-regression.sh` parses `by_op.read.latency_us`.
- For the crow-cli deep-pagination config: keys are `k{id:020}` (per
  `workload.rs` `format_key`), so `--scan-start-after` must use the
  same zero-padded format (e.g. `k00000000000000099989` for a 100k
  keyspace). The from-start companion uses an empty
  `--scan-start-after`.
- The sync `scan` UT mirrors `AsyncScan.StartAfterCursorSkipsEarlierEntries`
  (`async_scan_test.cpp` line 267) but exercises the sync `scan` path
  directly. Use the same `make_key` / `put_one` helpers already used
  by `ReadPath.ScanOrderLimitTruncatedAcrossLeaves` (line 144) so the
  test fits the file's existing style.
- L0-overlay scan perf is not measured by either layer in R46 (the
  client cannot hold the server's flush off; the C++ layer is a
  correctness UT only). Noted as a future gap in the baseline doc;
  existing `ReadPath.L0OverridesL1` / `ReadPath.L0TombstoneHidesL1`
  UTs cover L0-overlay scan correctness.
